# Domain Docs

## Layout and reading rules

This repo uses a single-context layout:
- `GLOSSARY.md` at the repo root for domain terminology.
- `docs/adr/` for architecture decision records.

Before exploring, read the glossary and ADRs relevant to the work.
If they do not exist, proceed silently. The domain-modeling skill
creates them lazily as terms and decisions are resolved.

## Vocabulary

Use glossary terms in issue titles, proposals, hypotheses, and tests.
If a needed concept is missing, reconsider the wording or note the
gap for domain-modeling.

## ADR conflicts

Explicitly flag any proposal that contradicts an existing ADR,
identifying the ADR and the reason to reopen its decision.
